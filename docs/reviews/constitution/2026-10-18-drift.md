## Summary

On 2026-10-18 the maintainer narrowed the project to keg tap-handle labels:
homebrewers first, with taprooms, restaurants and breweries welcome. The app
was renamed KegInker (#38). The constitution still describes a general
NFC e-paper writer that aims to support as many displays as possible.
Principles 1–4 still hold; the mission, audience, principle 5 and the
non-goals need updating, and the success criteria lack ids and checks.

## Drift findings

### [MAJOR] Mission describes a generic e-paper writer
- **Section:** Mission
- **Current text:** "Make battery-free NFC e-paper tags pleasant and dependable to use from a phone: pick an image, see exactly how it will look, tap, and trust that it worked."
- **Evidence of drift:** the rename to KegInker (#38, `feat!: rename the app to KegInker`); the repo description now reads "app for keg tap-handle labels"; #29 (templates and presets) calls keg labels "the main thing KegInker is for".
- **Proposed update:** "Keep every tap handle showing what's pouring. KegInker writes labels to battery-free NFC e-paper tags on keg tap handles from a phone: pick the beer, see exactly how the label will look, tap, and trust that it worked."

### [MAJOR] Audience says anyone with these tags is equally served
- **Section:** Audience
- **Current text:** "People who use NFC e-paper tags as small rewritable labels. The first and defining case is homebrewers labelling keg tap handles, who rewrite a tag every time a keg changes. Anyone else with these tags should find the app equally useful."
- **Evidence of drift:** the maintainer's decision to lean into tap handles because the template feature (#29) only makes sense there; "equally useful" for every tag use now contradicts that.
- **Proposed update:**
  "**This is for:** homebrewers labelling keg tap handles, who rewrite a tag every time a keg changes. Taprooms, restaurants and breweries rotating many taps are welcome and shouldn't hit a ceiling.
  **This is not for:** people after a general-purpose e-paper writer for photo frames, name badges or shelf labels. Vendor apps and generic writers serve them better."

### [MAJOR] Principle 5 aims for as many displays as possible
- **Section:** Principles
- **Current text:** "**Many displays, one app.** Support as many NFC e-paper displays as possible, across vendors, behind one consistent flow."
- **Evidence of drift:** with a tap-handle focus, display breadth is no longer a goal in itself; #24 (a collector for unsupported displays) serves the breadth goal. README still says "the goal of supporting as many NFC e-paper displays as possible".
- **Proposed update:** "**Displays that fit a tap handle, over display count.** Support the NFC e-paper panels that suit tap handles, across vendors, behind one consistent flow. Add a panel when tap-handle users need it, not to grow the list."
