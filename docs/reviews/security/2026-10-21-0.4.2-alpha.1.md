# Security review — v0.4.2-alpha.1 (2026-10-21)

Issue #45. This is the first full security review, as CONSTITUTION.md C6
requires for every minor release. It covers the code that the first
non-alpha release will be built from. There are no critical or high
findings. The two findings that affect users were fixed alongside this
report, and every other finding is tracked in an issue or accepted below.

## Scope

- **Reviewed:** `main` at `8316c339671f9146c9179e12f3bed91f17a9b816`,
  tagged v0.4.2-alpha.1, for both platforms.
- **In:**
  - NFC input handling: the shared Waveshare reply checks and `FoundTag`
    classification, the read-only display probe and NDEF parsing, Android's
    `NfcTransport` and `TagReader`, and iOS's `Iso7816Transport`,
    `MiFareTransport`, `TagWriter` and `DisplayProber`.
  - Decoding images the user picks: the Android photo picker path and the
    iOS `PhotosPicker` path, then resize and dither.
  - Diagnostics reports: what they contain, sharing, and the prefilled GitHub
    issue link.
  - Platform configuration: the Android manifest and release build, and the
    iOS `Info.plist` and entitlements.
  - The six GitHub Actions workflows, release signing and provenance, Gradle
    dependencies and the wrapper. There are no Swift packages.
- **Out:** penetration testing of third-party apps, tag firmware and
  hardware.

## Threat model

KegInker has no server and no `INTERNET` permission. It reads and writes
tags that the user holds to the phone, and decodes images that the user
picks. The attackers considered:

- **A malicious or malformed tag**, including a phone or Proxmark emulating
  one. It controls every reply byte, its timing, and the identity it claims.
- **A malicious picked image.** The user can be sent a file crafted to
  exhaust memory.
- **A compromised dependency, action or pull request** that reaches the
  build, signing or release.

## Method

1. A manual review of the code, in three parallel passes: NFC input
   handling; image decoding and diagnostics reports; configuration, CI and
   dependencies. Each finding was checked against the code, cited by file
   and line, and graded by impact and likelihood under the threat model.
2. Current outside results, used as inputs:
   - CodeQL and Scorecard alerts: 7 open, all from Scorecard posture checks;
     none is a code vulnerability.
   - Dependabot alerts: none.
   - The OpenSSF Scorecard result: 6.1/10. Token-Permissions,
     Pinned-Dependencies, Dangerous-Workflow and Vulnerabilities each score
     10.
3. Triage: overlapping findings were merged, severities settled, and small
   fixes made with regression tests. `./gradlew check` passes with them.

## Resolutions

### Fixed

- **NFC-1 (also found as DIAG-1):** Reports show only the start of a tag's ID,
  but the Type 2 probe kept reading until it found an NDEF message, up to
  40 reads. On MIFARE
  Ultralight and NTAG21x tags, a read near the last page wraps around to
  page 0. A tag with a blank or unformatted data area could therefore put
  its full ID into a report meant for a public issue. The probe now reads
  only the data area that the capability container declares, and near the
  end it reads the last four pages instead of reading past them. It stops
  after the first read when the capability container lacks its `E1` magic
  byte or declares no data area, which covers blank and unformatted tags.
  `DisplayProbeTest` covers each case.
  - **Remaining limit:** the bound trusts a well-formed capability
    container. A tag formatted to declare more memory than it has can still
    wrap. That takes a deliberately misformatted tag, and the user still
    sees the full report before sharing it.
  - **Not yet confirmed on a real tag:** the wrap-around comes from the
    datasheets, so the fix is deliberately defensive.
- **NFC-2:** On Android, "Advanced" stays available while a write waits for
  a tag. Opening "Report a display" didn't disarm that write. Once the probe
  had read one tag, the next one went to the waiting write and was
  overwritten, breaking the promise that the probe writes nothing. Opening
  "Report a display" now cancels a waiting write first, and a failed
  write keeps its warning and report. `AppTest` covers both. The overwrite
  test fails without the fix. iOS isn't affected: each flow there
  has its own Core NFC session.

### Tracked

- **#97, release-job hardening (CI-1, CI-2, CI-3, CFG-1):** each release job
  runs Gradle, and on iOS the Gradle build phase in the Xcode archive, while
  it holds the signing key, the App Store Connect key, a `contents: write`
  token and `id-token: write`. A compromised plugin or dependency could take
  the keys, or swap the build before it is attested. Pinned actions, scoped
  tokens and Dependabot limit how such code gets in. The issue separates
  building from publishing and moves the secrets into a protected
  environment.
- **#98, NFC deadline (NFC-3, NFC-5):** an emulated tag that answers each
  command just under the 3 s timeout can keep the Android UI on "Writing" or
  "Reading" for minutes, until the phone is lifted away. iOS is bounded by
  Core NFC's session limit.
- **#99, image limits (IMG-1, IMG-2, IMG-3):** a very large or highly
  compressed picked file can run the app out of memory. Only the user can
  trigger this, with a file they chose, and the decoded output is already
  limited to 1024 px. All the size arithmetic was checked and is
  overflow-safe.
- **#100, report hygiene (DIAG-2 to DIAG-5):** reports stay plain text, so
  nothing in them is rendered as markup. These items make what a report
  shows, and what PRIVACY.md says about it, exact.
- **#101, supply-chain controls (CI-4, CI-5, DEP-1):** these are good today
  by convention, and the issue makes them enforced.

### Accepted

- **NFC-6:** Any device that reports the Waveshare ID or ATS is treated as a
  display. It receives the label image and the vendor's fixed unlock key.
  Both are already public: the label is meant to be seen, and the key is the
  vendor's published constant. Writing also always starts with the user.
- **CFG-2:** The only app data is one on/off setting, so backups expose
  nothing.
- **CFG-3:** The app is open source and holds no secrets, so minifying adds
  no protection.
- **CI-6:** Attestations live in GitHub's attestation store, and
  `gh attestation verify` checks them (C5). Attaching them as release assets
  would raise the Scorecard score but wouldn't improve how releases are
  verified.
- **DEP-2:** CI installs the matching JDK through `setup-java`, so the
  toolchain download URLs aren't used there.

## Areas checked and found sound

- **Tag replies:** every parser checks lengths before indexing.
  - The NDEF parser checks 32-bit payload lengths against the bytes left
    before allocating anything, and its input is capped at 1,024 bytes.
  - Type 4 probe reads always finish.
  - Exceptions become failures the user sees, with a report and a retry.
  - The Swift NFC code has no force-unwraps.
- **Logging:** NFC frame logs exist only in debug builds on both platforms.
  Image data never enters a report: only a byte count is recorded.
- **Reports and privacy:**
  - A report holds the app version, the device model and OS, and at most
    the first half of the tag ID.
  - It holds no device identifier and no location.
  - Nothing leaves the phone unless the user taps something.
  - The issue link has a fixed host, is percent-encoded and is
    length-checked.
- **Images:** both pickers grant access only to the chosen image, and
  neither app requests photo-library permission. Image metadata is not
  read.
- **Android:**
  - Only the launcher activity is exported.
  - No NFC intent filter lets a tag start the app, because reading happens
    only in the foreground.
  - The app requests only the `NFC` permission.
  - Release builds aren't debuggable.
  - The signing configuration fails if a password is missing.
- **iOS:**
  - The entitlements grant only tag reading.
  - Release archives refuse a Debug configuration.
- **Workflows:**
  - No workflow uses `pull_request_target` or `workflow_run`.
  - Pull requests from forks never receive secrets.
  - No event data is interpolated into a shell command.
  - Every action is pinned to a commit SHA.
  - Token permissions are read-only by default.
  - A release needs a tag on `main` with a matching release-please release.
- **Dependencies:**
  - Versions are current, with no known vulnerabilities.
  - The Gradle wrapper checks its distribution checksum, and CI validates
    the wrapper jar.
  - The `google()` repository is limited to Google's groups.
